01 / REQUEST LIFECYCLE

From one request to a recorded outcome.

Your application sends a standard text-chat request. Relay handles admission, model selection, provider translation, and accounting.

01

Validate access

Relay hashes the bearer API key and looks it up in PostgreSQL. Revoked keys stop here.

02

Claim a quota token

An atomic Redis token bucket enforces the same per-key quota across gateway instances.

03

Record the request

A pending PostgreSQL row is created before any classifier or provider call.

04

Classify and select

The local classifier or optional Jev selects a complexity tier. Your configuration maps that tier to an ordered model route. Explicit routes bypass classification.

05

Execute with bounded fallback

Provider adapters translate the request. Retryable failures advance to the next target, within per-attempt and overall deadlines.

06

Finalize the ledger

The outcome and provider attempts commit together. Relay returns normalized usage, timing, estimated cost, and the request ID.

02 / MODEL ROUTING

Intelligence in the decision. Policy in your code.

Set model: "auto" to classify complexity. Simple tasks can use a fast model; ordinary coding or writing can use a balanced model; harder reasoning can use a more capable model. These assignments are configurable, not claims about a particular vendor.

SimpleExtraction, translation, short questions
StandardExplanations, coding, comparisons
ComplexArchitecture, proofs, difficult debugging

When enabled, Jev gets one bounded call. Low confidence, a timeout, or an invalid result selects the configured default route. A provider override bypasses classification. Client cancellation prevents further attempts.

03 / SHARED STATE

Quotas and records outlive a process.

Redis maintains request quotas using an atomic Lua script and server time. Requests consume one token, including requests that fall back across multiple providers.

PostgreSQL stores hashed API keys and request metadata: model, provider, timestamps, tokens, latency, estimated cost, status, routing decisions, and every provider attempt. Prompts and generated text are not persisted.

Completion costs and classifier costs are accounted separately. Simulated usage is explicitly labeled. Costs are estimates rather than invoice reconciliation.

04 / WHAT YOU CAN TRY HERE

Real routing. Transparent simulation.

The public workspace runs the same Go router, local classifier, fallback logic, provider interface, and cost arithmetic as the gateway. Each request reaches the server; results are not prerecorded.

It uses only simulated completion providers and the offline classifier. It does not call Jev or paid model APIs, issue private API keys, or write to a shared public ledger. The latest 20 results stay in your browser's memory until you reload or clear the session.

The public deployment is a bounded, stateless Vercel service. The full authenticated gateway uses PostgreSQL and Redis when self-hosted. The public workspace does not claim to exercise those storage dependencies.

Choose a primary 429, 500, or timeout to observe fallback. Choose “No available provider” to see Relay stop with a structured error.

05 / SELF-HOST

Your gateway, on your machine.

Install Docker with Compose. Clone Relay, generate unique local credentials, and start the stack:

terminal 
git clone https://github.com/KennyMx/Relay.git
cd Relay
docker compose run --rm --build --no-deps \
  --user "$(id -u):$(id -g)" -v "$PWD:/setup" \
  gateway init /setup/.env
docker compose up --build

Open localhost:8080/console. Use the admin token from your private .env to create a Relay key, then send requests. The full local stack starts with mock providers, so no provider keys or API charges are required.

To enable Jev, set RELAY_CLASSIFIER=jev and JEV_API_KEY. For real completions, configure provider keys, model targets, and pricing. External API calls may incur charges.

06 / DELIBERATE BOUNDARIES

A focused gateway, with explicit tradeoffs.

  • Non-streaming text chat, with a small unified API surface.
  • Bounded retries do not guarantee exactly-once provider billing. A timed-out upstream may still charge.
  • No transaction spans Redis, PostgreSQL, and the external providers. Process crashes may leave a pending record.
  • Classification is a routing signal, not a guarantee of answer quality.
  • The public workspace has a per-instance concurrency bound, not the full gateway's Redis quota system.
